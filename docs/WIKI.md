# Вики мода — исчерпывающий внутриигровой справочник

Клавиша **P** (или вкладка «Вики» в хабе **H**) открывает полноэкранную вики: слева — дерево
категорий и поиск, в центре — страница в Markdown с гиперссылками, справа — витрина предмета
с «поворотом» и связанные страницы.

Это не набор статических подсказок: вики — это **каталог .md-файлов**, который читается
из ресурсов мода при первом открытии экрана. Чтобы добавить или исправить страницу, не нужно
трогать Java-код — достаточно отредактировать (или перегенерировать) файл в
`src/main/resources/assets/mmorpg/wiki/`.

Категории: `start` Начало, `combat` Бой, `world` Мир, `items` Предметы, `craft` Ремесло,
`gems` Самоцветы, `runes` Руны, `runewords` Рунные слова, `currency` Валюта и сферы,
`uniques` Уникальное снаряжение, `materials` Материалы, `systems` Системы, `meta` Справка.

## Формат каталога

### Манифест `wiki/index.txt`

```
;; комментарий
# home start/overview
# category start Начало
start/overview
start/first-hour
```

* `# home <id>` — стартовая страница (открывается по `P` без аргумента);
* `# category <id> <Название>` — заголовок группы в левом дереве;
* строка `<id>` — страница; файл лежит в `wiki/ru/<id>.md` (id может содержать `/`).

### Страница `wiki/ru/<id>.md`

```
@title Турмалин (Tourmaline)
@en Tourmaline
@category gems
@tags самоцвет,камень,выживание
@item mmorpg:gems/tourmaline/0
@item mmorpg:gems/tourmaline/1

## Что это

Текст страницы в Markdown…
```

* `@title` — русское название (заголовок страницы), `@en` — английское;
* `@category` — id категории из манифеста (обязателен и должен совпадать);
* `@tags` — через запятую, участвуют в поиске;
* `@item mmorpg:…` — повторяемая строка: id предмета из реестра мода. Первый найденный предмет
  показывается на витрине справа. Сюда можно писать только **реально зарегистрированные** id,
  иначе чекер ругнётся, а экран просто проигнорирует строку.

### Разметка

Поддерживается ровно то, что нужно каталогу:

* заголовки `#`, `##`, `###`;
* абзацы, списки `-` и `1.`, цитаты `>`, таблицы `| a | b |`, разделители `---`;
* инлайн: `**жирный**`, `*курсив*`, `` `код` ``;
* ссылки: `[текст](gems/overview)`, `[[gems/overview]]`, `[[gems/overview|текст]]`.

Ссылка — это id страницы, а не URL. Парсер терпимый: незнакомая разметка остаётся текстом,
битый `.md` не ломает экран.

## Экран

* **Поиск** (`/` или клик по строке) — по названию, английскому названию, тегам, id и тексту.
* **История** — `←`/`→` (стрелки) или кнопки в шапке; `✦` — случайная страница.
* **Прокрутка** — колесо: над деревом листает дерево, над текстом листает текст.
* **Гиперссылки** — клик по подчёркнутому тексту; при наведении показывается название цели,
  внизу справа — соседние страницы категории и блок «Ссылаются сюда».
* **Витрина** — предмет вращается на орбитах-«пьедестале»: плоская иконка растягивается и
  отражается по фазе, создавая объём. Настоящего 3D-рендера предметов в совместимом слое нет,
  поэтому это честная имитация, а не `.json`-модель.

Экран не падает: если каталог не загрузился, показывается страница-заглушка с причиной
и кнопка «случайная страница» работает по тому, что удалось прочитать.

## Генератор и проверка

```
python3 tools/wiki/build_wiki.py    # пересобрать весь каталог
python3 tools/wiki/check_wiki.py    # проверить каталог
```

Генератор читает исходники мода (самоцветы, руны, валюту, уникаты, ингредиенты, формулы защиты)
и пишет 113 страниц. Ручные тексты гайдов лежат прямо в `tools/wiki/build_wiki.py` — это
единственное место, где их надо править, чтобы они не потерялись при пересборке.

`check_wiki.py` — самопроверка «не баганая»:

1. манифест ↔ файлы: каждая страница на месте, лишних `.md` нет, `# home` существует;
2. у каждой страницы есть `@title`, `@en`, `@category`, категория совпадает с манифестом;
3. текста без разметки не меньше 1 000 символов;
4. все ссылки `[[…]]` и `[…](…)` ведут на существующие страницы;
5. нет страниц-сирот (на каждую есть хотя бы одна ссылка);
6. каждый предмет из реестра (самоцветы, руны, валюта, ингредиенты, инструменты, улучшения
   рюкзака, зелья, расходники, эссенции, камни) имеет страницу;
7. в `@item` нет опечаток: id сверяется с тем, что регистрирует код.

Чекер включён в `tools/verify.sh` (шаг 5 из 6). В песочнице шаг компиляции пропускается —
реальная сборка выполняется на машине с JDK 25.

## Как добавить страницу

1. Дописать текст в `tools/wiki/build_wiki.py` (функция `guide(...)` или `add(...)`) — либо
   создать файл вручную.
2. Добавить id в `index.txt` под нужной категорией.
3. `python3 tools/wiki/build_wiki.py` (если правили генератор) и `python3 tools/wiki/check_wiki.py`.
4. Открыть игру: `P` → найти страницу поиском.

Если страница короче 1 000 символов, чекер не пропустит — это осознанный критерий: короткая
страница не отвечает на вопрос «а что это и зачем».
