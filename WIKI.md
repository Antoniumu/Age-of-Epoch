# Вики Эпохи — внутриигровая энциклопедия мода

Полноценная вики внутри игры: страница на **каждый** предмет и блок мода
с вращающейся 3D-моделью, подробным объяснением обычными словами, рецептами
и гиперссылками, плюс исчерпывающие гайды по всем механикам — от типов урона
и уклонения до порчи, рунных слов и класса «Божественный».

Открывается: **H** (хаб) → вкладка **«Вики»**. Старый экран вики
(`gui/screens/wiki/WikiScreen`, 4 вкладки реестра) из хаба отключён, но его
классы не тронуты — возврат в один коммит.

**Быстрый вход прямо из инвентаря:** наведите курсор на предмет и удерживайте
**B** (переназначается: Настройки → Управление → «Удерживать на предмете:
открыть в Вики Эпохи») — прямо в тултипе заполняется полоса
`Вики Эпохи ██████░░░░░░ 53%`, и через ~0,65 с вики сама открывается:
предмет мода — на его статье, снаряжение с данными — в гайде по снаряжению,
ванильный ингредиент — в поиске по рецептам с ним. Подсказка
`[B] удерживать — открыть в Вики Эпохи` висит серой строкой в тултипах
предметов со своей статьёй. Реализация: `wiki/WikiHoldToOpen.java`
(полоса и очередь) + хук в `TooltipMethod` + открытие из клиентского тика
`OnKeyPress` (экраны не меняем посреди рендера). Открытие из контейнера
закрывает текущий инвентарь — как любой переход на новый экран.

## Что умеет экран

- **Адаптивная вёрстка без текстур**: тёмная «стеклянная» панель с золотой
  рамкой растягивается под окно (как плашки мобов MODERN), справа на широких
  окнах — карточка предмета, на узких статья получает всю ширину.
- **Вращающаяся модель справа**: предмет рендерится в ×3.1 на пьедестале,
  парит и вращается; для блоков это настоящая объёмная модель игры, плоские
  предметы вращаются турнтейбл-анимацией GUI. Модель можно крутить
  перетаскиванием мыши, при наведении — игровое имя, ID и подсказка.
- **Гиперссылки**: `[[страница|подпись]]`, `[[страница#якорь|подпись]]`,
  `[[#якорь|подпись]]` и `[подпись](страница)` — с подсветкой при наведении
  и тултипом названия страницы. Назад/вперёд/главная хранят историю и
  переживают переоткрытие экрана.
- **Поиск** по русским/английским названиям, ID, тегам и полному тексту
  (совпадения в названии выше), фильтры-чипсы «Все/Гайды/Разделы/Предметы»,
  прокрутка колесом по зонам, стрелки/PageUp/PageDown для статьи.
- **Не роняет игру**: парсер markdown никогда не бросает исключений на битом
  вводе, битая страница пропускается, а при пустом каталоге экран показывает
  страницу-объяснение вместо краша.

## Контент: исчерпывающий каталог .md

Страницы лежат в `src/main/resources/assets/mmorpg/wiki_pages/` и
**генерируются** из настоящих данных мода:

```bash
python3 tools/wiki_gen/generate_wiki.py   # пересобрать весь каталог
python3 tools/wiki_gen/verify_wiki.py     # проверить (код 1 при любой проблеме)
```

Генератор читает `assets/<ns>/items/*.json` (все 287 предметов),
`blockstates` (ещё 24 блока без предметов), `lang/ru_ru.json` и `en_us.json`
(названия + описания по Alt, ключи `mmorpg.item.desc.*` и семейства) и
`data/<ns>/recipe/*.json` (рецепты и обратный индекс «где используется как
ингредиент»). Каждая страница предмета: что это такое → как получить
(рецепты со ссылками на ингредиенты) → как пользоваться (по шагам из
описания) → важные детали → связанные страницы → справка с ID.

Гайды по механикам написаны вручную простым языком в
`tools/wiki_gen/wiki_guides.py` (34 гайда: урон, защита, криты, ресурсы,
редкости, валюта/нестабильность/порча, самоцветы с таблицей 9×3, рунные
слова с порядками рун, профессии, разбор, башни, подземелья, экспедиции,
миссии, «Божественный», словарь, FAQ…) и вливаются в каталог генератором.

### Жёсткое правило длины

Каждая страница каталога обязана содержать **не менее 1000 видимых символов**
текста (без разметки; у ссылок считается подпись). `verify_wiki.py` проверяет
это для всех 371 страниц, а также: страница есть на каждый предмет/блок, все
`[[ссылки]]` и `#якоря` разрешаются, frontmatter валиден, `item:` существует
в моде. Сейчас: самая короткая страница — 1013 символов, медиана — 2309.
Проверка подключена в `tools/verify.sh` (шаг 2).

### Формат страницы

```markdown
---
title: Божественный рубин
item: mmorpg:gems/ruby/6
category: gems
category_label: Самоцветы
tags: Самоцветы, Divine Ruby, gems/ruby/6
---
# Божественный рубин

**Божественный рубин** — … См. [[guides/gems|Самоцветы]] …
```

ID страницы — путь файла без `.md` (`items/gems_ruby_6`, `guides/damage`,
`categories/currency`, главная — `index`). Диалект markdown поддерживает:
заголовки `#`–`###`, абзацы, списки `-` и `1.`, цитаты `>`, разделители
`---`, таблицы `| a | b |` (строками), код-блоки ``` , инлайн
`**жир**`, `*курсив*`, `` `код` `` и ссылки выше. Slug якоря: нижний регистр
заголовка, пробелы → `-`.

### Добавить предмет или гайд

- Новый предмет мода: просто перегенерируйте каталог. Если описания по Alt
  ещё нет, `tools/audit_item_descriptions.py` и `verify_wiki.py` на пару
  покажут, чего не хватает.
- Новый гайд: допишите запись в `GUIDES` (`wiki_guides.py`), добавьте его в
  `GUIDE_TOC` генератора, перегенерируйте и проверьте. Гайд короче 1000
  символов проверку не пройдёт — это намеренно.

## Код

| Файл | Что |
|---|---|
| `src/main/java/com/robertx22/age_of_exile/wiki/WikiMarkdown.java` | Чистый Java-парсер диалекта (без Minecraft): frontmatter, блоки, инлайн, якоря. Не бросает исключений. |
| `…/wiki/WikiCatalog.java` | Ленивая загрузка всех `.md` из ресурсов (`listResources`), кэш, поиск, fallback-страница. |
| `…/wiki/ModWikiScreen.java` | Экран (замена `WikiScreen` в хабе): вёрстка, ссылки, история, поиск, фильтры, вращающееся превью предмета. |
| `…/wiki/WikiHoldToOpen.java` | Удержание B на предмете: полоса прогресса в тултипе (`TooltipMethod`) и открытие статьи из клиентского тика (`OnKeyPress`). Клавиша — `KeybindsRegister.WIKI_HOLD_KEY`. |
| `tools/wiki_gen/generate_wiki.py` | Генератор каталога из данных мода. |
| `tools/wiki_gen/wiki_guides.py` | Ручные гайды. |
| `tools/wiki_gen/verify_wiki.py` | Проверка каталога (покрытие, ≥1000 символов, ссылки, frontmatter). |
| `tools/wiki_gen/WikiMarkdownTest.java` | Автономный тест парсера без игры (только JDK). |

Тест парсера на машине с JDK:

```bash
mkdir -p /tmp/wiki-test
javac -encoding UTF-8 -d /tmp/wiki-test \
  src/main/java/com/robertx22/age_of_exile/wiki/WikiMarkdown.java \
  tools/wiki_gen/WikiMarkdownTest.java
java -cp /tmp/wiki-test WikiMarkdownTest src/main/resources/assets/mmorpg/wiki_pages
```

## Статус и честные ограничения

- В песочнице разработки Minecraft не собирается (нет JDK 25 и доступа к
  Mojang/Fabric Maven — см. `PORTING.md`), поэтому экран не запускался в
  живой игре. Проверено всё, что проверяется без игры: каталог целиком
  Python-верификатором, синтаксис новых Java-файлов независимым парсером,
  а обращения к API сведены к паттернам уже существующих экранов
  (BaseScreen/AbstractGui/QuestBookScreen) и реестров (`getValue(parse)`).
  Окончательная приёмка: `./gradlew runClient` → H → «Вики».
- Клавиатура поиска подключена тремя путями доставки событий сразу:
  ванильные `KeyEvent`/`CharacterEvent` (26.x) и int-сигнатуры
  compat-слоя — какой путь живой в конкретном билде, тот и сработает;
  навигация стрелками и кликами работает независимо от этого.
- Вращение модели: GUI-экстракция 26.x рендерит предмет через
  `GuiGraphicsExtractor.item` с 2D-стеком поз, публичного «вращения вокруг Y»
  у неё нет; поэтому блоковые модели видны как есть (объёмная модель игры),
  а плоские предметы получают честную турнтейбл-анимацию сжатия + парения
  и ручное вращение перетаскиванием.
- Реестры уникатов/сетов/эффектов из живой базы ExileDB по-прежнему
  показывает старый экран вики в коде; в этой вики им посвящён гайд
  «Уникальные предметы и комплекты», а прогресс находок — в Книге Эпохи (K).
