# «Последний Рассвет»: первый нативный срез

**Последний игровой прогон: [40591863608](https://github.com/Antoniumu/Age-of-Epoch/actions/runs/40591863608) — SUCCESS.**
Сборка, 36 JUnit-тестов и настоящий клиент прошли. Проверены призыв, палуба,
лифт, отказ удалённого принятия, окно разговора, принятие кликом, карточка H
и все четыре этапа вводной цепочки. Скриншоты — `proof-images/`;
результаты сервера — `ci-proof.txt`. Сохранение после перезапуска сервера
отдельно этим сценарием не проверялось. NPC со скинами игроков и окончательный
минималистичный дизайн ещё не реализованы.

Встроено в **Age of Epoch**, без обязательной зависимости от NPC/диалогового мода.
Minecraft/Fabric — версии из `gradle.properties` (26.3). Это не законченная замена
всей кампании: существующий `questBook` и его события сохранены для миграции без
потери прогресса.

## Попробовать

1. Установить собранный мод **на сервер и клиент**. Новые пакеты требуют одинаковой версии.
2. В обычном мире собрать 8 изумрудов и ввести `/airship summon`.
   Для оператора есть бесплатный `/airship demo`.
3. В чате появятся координаты светового круга под кораблём. Войти в круг:
   первая реализация лифта мгновенно переносит на палубу, с частицами.
4. ПКМ по капитану → **Принять поручение**. H открывает прежний экран персонажа,
   в верхнем правом углу появляется карточка квеста с головой его автора.
   Голова и глаза слегка смещаются за курсором. Это авторский 2D pixel-art,
   не 3D-модель NPC и не спутник в мире.
5. Поговорить с Марой → Брамом → капитаном. Все переходы подтверждаются кнопкой.
6. `/airship descend` — безопасный спуск под свой корабль.

## Что сделано

- Оригинальный процедурный дирижабль: корпус, палуба, перила, полосатый баллон,
  подвесы, фонари, мостик, стол картографа, припасы и магический двигатель.
- Три постоянных NPC на основе ванильного жителя. Их имена/роли разные;
  индивидуальных скинов и кастомных моделей жителей пока нет.
- Собственный экран разговора с портретом, текстом и явным принятием поручения.
- Короткая линейная вводная цепочка, без повторяемой награды предметами.
- Отдельные данные `airship_campaign` в RPGPlayerData: этап квеста и координаты
  причала сохраняются/синхронизируются штатным механизмом персонажа.
- Кнопка отправляет только ID сущности. Сервер проверяет NPC, расстояние,
  видимость, порядок этапов и не позволяет проходить цепочку повторными пакетами.
- Стоимость списывается только после проверки свободного места и создания команды.
- Размещение только в уже загруженных чанках Overworld, внутри границы мира,
  в полностью воздушном объёме с запасом вокруг корпуса, без посторонних сущностей.
  Старые блоки не заменяются. Подъёмная шахта тоже проверяется на воздух.
- Лифт не выдаёт долгоживущих эффектов левитации и не оставляет игрока падать.

## Сознательные ограничения

Это **не релиз для публичного сервера**. Нет интеграции с модами приватов:
проверка воздуха не означает разрешение строить в чужом регионе. До такой
интеграции не включать призыв на сервере с приватами. Нет отдельной защиты блоков
корабля от игроков, взрывов и огня. NPC неуязвимы, но операторы могут их удалить.

Один корабль на персонажа. Повторный призыв сообщает существующий причал;
перемещение, удаление и восстановление разрушенного корабля пока не реализованы.
Корабль — неподвижная постройка, а не физически летающая сущность. Не держит
чанки принудительно загруженными. Лифт работает для владельца причала.

Первые задания — знакомство с командой. Перенос всех старых глав, торговля,
обучающие подсказки, проигрывание голосов, дальний звук магического скачка и
плавная анимация подъёма — следующие этапы. MP3 в `audio/` — пробы, ещё не
ресурс-пак звуков Minecraft. Библиотека диалогов сейчас Java-таблица, не внешний
редактор сценариев.

## Проверки и настоящие скриншоты

- `AirshipStoryTest`: порядок этапов, защита от неизвестных NPC/повторных переходов,
  наличие текста и портретов для каждого этапа.
- `.github/workflows/airship.yml`: `./gradlew build`, затем настоящий dev-клиент
  под Xvfb, сценарий `tools/e2e/scenarios/airship.txt`.
- Сценарий снимает экстерьер, палубу, прибытие лифта, разговор и H-карточки.
  Первый квест принимает кликом по реальной кнопке. Остальные этапы выполняет
  серверный файловый dev-зонд с проверками. Удалённое принятие проверяется отдельно.
- Скриншоты, логи, JUnit-отчёт и jar — артефакт **airship-proof**. Workflow не
  создаёт и не пушит вспомогательные ветки.
- Наличие сценария не является доказательством его успешного выполнения:
  смотреть статус конкретного GitHub Actions run и его артефакт.

## Регрессия одиночной игры

При разборе игрового сбоя обнаружен риск коллизии общего compatibility-хранилища:
`Entity.equals/hashCode` используют числовой ID, поэтому `WeakHashMap` смешивал
клиентского и серверного владельца capabilities в одном JVM. Поздний клиентский
пакет потенциально мог заменить серверный `airship` старым зеркалом (включая координаты 0,0,0).
`CapabilityProvider` теперь использует слабые ключи с **identity**-сравнением.
`WeakIdentityMapTest` проверяет два разных, но `equals()`-равных экземпляра,
повторный lookup и независимость при перезаписи клиентского зеркала.


## История диагностики

Прогон 40589756516: компиляция и JUnit прошли; игровой тест не прошёл:
причал не установлен (`No clear mooring`). Исправление identity-хранилища
не устранило эту ошибку, поэтому считать его доказанной причиной сбоя нельзя.
Добавлена диагностика отказа каждой точки: поверхность, загруженность чанков,
граница мира, высота, воздушный объём и шахта лифта. Проверки безопасности
не ослабляются ради получения скриншота.

Следующее оформление по решению пользователя: NPC с моделью игрока и своими
скинами вместо жителей; портрет из того же скина. Диалог — минималистичный,
с пиксельным шрифтом и простыми вариантами ответа, без массивного декора.

Диагностический прогон 40591208071 уточнил отказ: проверенные точки
пересекались с рельефом, а трёхблочная шахта упиралась в соседний склон.
Высота теперь выбирается над всем габаритом корабля, точек поиска больше;
проверяется центральная колонна лифта с запасом для головы. Полная проверка
воздушного объёма корпуса сохранена; никакие существующие блоки не стираются.
