# Вики Age of Epoch

Внутриигровая энциклопедия мода: страницы предметов и блоков, справочные разделы и гайды по игровым системам. Открыть её можно из хаба (**H → «Вики»**) или удержанием **B** на предмете в инвентаре. Клавиша B переназначается в настройках управления.

## Возможности экрана

- Адаптивный экран: список страниц и поиск слева, статья по центру, карточка с моделью предмета и ссылками справа на широких окнах.
- Перекрёстные ссылки `[[страница|подпись]]` и якоря `[[страница#раздел|подпись]]`; кнопки назад, вперёд и главная.
- Поиск без учёта регистра с NFKC-нормализацией Unicode; русские `ё` и `е` считаются эквивалентными. Запрос из нескольких слов ищется в любом порядке по названию, тегам, ID страницы и предмета, а также тексту статьи. Названия ранжируются выше ID и текста. Пустой запрос показывает каталог, а пустой результат — отдельное сообщение.
- Перенос текста статьи по доступной ширине; прокрутка статьи и списка страниц колесом мыши.
- Битая отдельная страница пропускается с записью в лог. Если каталог не загрузился целиком, экран показывает объяснение вместо падения игры.

## Архитектура и исходные данные

Сгенерированные Markdown-страницы находятся в `src/main/resources/assets/mmorpg/wiki_pages/`. Каталог включает главную, категории, гайды и карточки предметов/блоков.

| Компонент | Назначение |
|---|---|
| `tools/wiki_gen/generate_wiki.py` | Воспроизводимо собирает страницы из данных ресурсов и датапака мода; `--check` сравнивает результат с каталогом без записи файлов. |
| `tools/wiki_gen/wiki_guides.py` | Рукописные гайды, которые генератор добавляет к автоматически созданным страницам. |
| `tools/wiki_gen/verify_wiki.py` | Проверяет покрытие предметов/блоков, frontmatter, ссылки и якоря, дубликаты абзацев, подозрительный текст и достижимость страниц от главной. Не задаёт искусственный минимум длины: проверяется, что у страницы есть видимый текст. |
| `src/main/java/com/robertx22/age_of_exile/wiki/WikiMarkdown.java` | Чистый Java-парсер markdown-диалекта и frontmatter, собирает ссылки и якоря. |
| `src/main/java/com/robertx22/age_of_exile/wiki/WikiCatalog.java` | Загружает страницы из Minecraft ResourceManager, кэширует их, обеспечивает поиск и резервную страницу. |
| `src/main/java/com/robertx22/age_of_exile/wiki/WikiSearch.java` | Нормализует запрос, находит и ранжирует совпадения; не зависит от Minecraft и тестируется отдельно. |
| `src/main/java/com/robertx22/age_of_exile/wiki/ModWikiScreen.java` | Рендерит каталог, поиск, статью, ссылки, историю и карточку предмета. |
| `src/main/java/com/robertx22/age_of_exile/wiki/WikiScreenshotCrawler.java` | Dev-only мост для CI: открывает запрошенную страницу в обычном экране клиента; в релизной среде не активен. |

Генератор использует определения предметов, blockstates, локализацию RU/EN, описания предметов и рецепты. Гайды редактируются вручную в `wiki_guides.py`. Автоматические карточки содержат доступное описание, конкретные рецепты и использования, связанные ссылки и справочные ID; шаблонные абзацы не добавляются только ради длины. Если у предмета нет рецепта или описания в данных мода, генератор не должен выдумывать их.

## Формат Markdown

ID страницы — путь файла относительно `wiki_pages` без `.md`: например, `index`, `guides/damage`, `categories/currency`, `items/gems_ruby_6`. Ссылки внутри каталога используют тот же ID.

Поддерживаемый диалект: заголовки `#`–`###`, абзацы, маркированные и нумерованные списки, цитаты `>`, разделители `---`, таблицы строками, блоки кода, инлайн-стили `**жирный**`, `*курсив*`, `` `код` `` и внутриигровые ссылки `[[page|label]]`, `[[page#anchor|label]]`. Якорь строится из текста заголовка: нижний регистр, пробелы заменяются дефисами.

Frontmatter начинается и заканчивается строкой `---`; используемые поля — `title`, `item`, `category`, `category_label`, `tags`. Поле `item` содержит registry ID для модели предмета и должно соответствовать ресурсу мода.

## Проверки и запуск

Для генерации и проверок каталога достаточно Python 3:

```bash
# Пересоздать Markdown-файлы из исходных данных
python3 tools/wiki_gen/generate_wiki.py

# Убедиться, что каталог актуален; файлы не изменяются
python3 tools/wiki_gen/generate_wiki.py --check

# Проверить страницы, ссылки, якоря, ID и навигацию
python3 tools/wiki_gen/verify_wiki.py
```

Добавив или поменяв исходник страницы, выполните генерацию, затем обе проверки. `--check` используется в CI, поэтому устаревшая или лишняя сгенерированная страница не проходит проверку незаметно.

Java-тесты парсера и поиска выполняются JDK 25 и Gradle:

```bash
./gradlew test \
  --tests 'com.robertx22.age_of_exile.wiki.WikiMarkdownTest' \
  --tests 'com.robertx22.age_of_exile.wiki.WikiSearchTest'
```

`WikiMarkdownTest` проверяет синтаксис парсера и весь каталог, включая ссылки и якоря; `WikiSearchTest` покрывает пустой запрос/результат, Unicode, составные запросы, ID и ранжирование.

## CI и скриншоты всех страниц

- `.github/workflows/ci.yml` запускает `tools/ci/static-checks.sh`: проверку актуальности генерации и валидатор wiki, а build job выполняет Gradle-тесты.
- `.github/workflows/screenshots.yml` поднимает dev-клиент в Xvfb для pull request и `main`. По умолчанию в `tools/e2e/active.txt` включён сценарий `wiki`.
- В конце `tools/e2e/scenarios/wiki.txt` команда `wiki_crawl` перечисляет все `.md`-страницы, открывает каждую через `ModWikiScreen` и сохраняет отдельный PNG. Артефакт `client-screenshots` содержит папку `wiki/`, манифест `wiki-pages.tsv`, пошаговый журнал и логи. Артефакт хранится в GitHub Actions 14 дней; PNG не коммитятся и не публикуются в Git-ветки.
- Шаг CI запускает `tools/e2e/verify_wiki_screenshots.py`: сверяет манифест с каталогом, проверяет наличие отдельного непустого изображения для каждой страницы. Отсутствующая страница или снимок делает проверку красной.

Локальный прогон скриншотов требует JDK/Gradle и системных пакетов для Xvfb, X11 и ImageMagick (их список есть в workflow):

```bash
bash tools/e2e/run-in-xvfb.sh \
  tools/e2e/scenarios/wiki.txt run/e2e/shots/wiki
python3 tools/e2e/verify_wiki_screenshots.py run/e2e/shots/wiki
```

Для ручного запуска только части E2E-сценариев укажите имена файлов через `workflow_dispatch → scenario`. Не включайте PNG в Git; локальный каталог `run/` игнорируется.

## Ограничения и приёмка

Генератор покрывает ресурсы, рецепты и рукописные гайды, но не является редактором всех динамических баз мода (например, полного реестра уникальных предметов/комплектов из ExileDB). Для динамических механик используйте соответствующие гайды и игровые подсказки. Скриншоты и живой экран проверяются только запуском клиента; статический Python-валидатор не заменяет эту проверку.

Для локальной приёмки нужны JDK 25, Gradle-зависимости и графическое окружение либо Xvfb. Если этих компонентов нет, запускайте Python-проверки локально, а Java-тесты, сборку клиента и полное снятие скриншотов проверяйте в GitHub Actions. CI является источником итогового результата для всех страниц каталога.
