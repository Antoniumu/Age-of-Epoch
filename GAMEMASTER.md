# GameMaster — динамическая подстройка опыта и спавна

Система для серверов Age of Epoch, которая настраивает **скорость развития игроков** и
**появление враждебных мобов рядом с ними**. В ней четыре независимые функции:

0. **Автобаланс** — «режиссёр», который сам держит игрока в коридоре темпа
   (≈14→70 минут на уровень, суммарно ≈28 часов до 50-го) и подстраивает под него
   опыт, живучесть/урон мобов и лут. Не фиксированные N часов, а «оптимально долго»:
   коридор расширяется по ходу игры и подстраивается под реальный темп игрока.
1. **Уравнивание игроков (catch-up)** — отстающие получают больше опыта, ушедшие вперёд — меньше.
   Группа развивается вместе, даже если кто-то начал позже.
2. **Темп развития (pacing)** — общий штраф к опыту после заданного уровня, чтобы путь
   до максимального уровня занимал около **заданного числа реальных часов** (по умолчанию 100).
   Штраф автоматически калибруется по фактическим замерам времени игры.
3. **Spawn-rate мобов** — ручная настройка и динамическое уменьшение естественного спавна
   враждебных мобов, обычных блоков-спавнеров и спавнеров комнат данжей в зависимости от
   Благосклонности ближайшего игрока.

Общий выключатель (`enabled`) отключает вмешательство GameMaster в опыт и спавн,
не прекращая сбор статистики.

Всё настраивается тремя способами: JSON-конфиг, команды `/mine_and_slash gm ...`
и локальная веб-панель с графиками прогресса всех игроков.

## 1. Уравнивание игроков

Для каждого игрока считается **ориентир группы**:

```
средний = средний уровень всех «сезонных» игроков
максимум = уровень самого высокого из них
ориентир = средний + blend × (максимум − средний)      // blend = 0.35 по умолчанию
```

«Сезонными» считаются игроки, которые наиграли хотя бы `catch_up_min_playtime_minutes`
(по умолчанию 30 минут) и заходили за последние `catch_up_activity_window_days` дней
(по умолчанию 30). Мёртвые/заброшенные аккаунты не тянут ориентир вниз.

При `blend = 0` группа равняется на средний уровень, при `blend = 1` — на лидера.
Значение 0.35 — компромисс: подтягиваемся к «чуть выше среднего», но не гоним всех за топом.

Множитель:

```
Δ = ориентир − уровень игрока

если Δ > 0:   ×(1 + min(catch_up_max_bonus, catch_up_per_level × Δ))
если Δ < 0:   ×max(catch_up_min_multiplier, 1 − catch_up_penalty_per_level × |Δ|)
иначе:        ×1
```

Значения по умолчанию:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `catch_up_per_level` | 0.25 | +25 % опыта за каждый уровень отставания |
| `catch_up_max_bonus` | 2.0 | максимум +200 % (итого ×3) |
| `catch_up_penalize_ahead` | true | штрафовать ли опережающих |
| `catch_up_penalty_per_level` | 0.05 | −5 % за каждый уровень опережения |
| `catch_up_min_multiplier` | 0.5 | опережающий получает не меньше ×0.5 |
| `catch_up_reference_blend` | 0.35 | ориентация на средний/лидера |

Пример: ориентир 35-й уровень.

* игрок 20-го уровня: Δ = 15 → ×(1 + 0.25 × 15) = ×4.75, но обрезается до ×3.0;
* игрок 32-го уровня: Δ = 3 → ×1.75;
* игрок 40-го уровня: Δ = −5 → ×0.75;
* игрок 45-го уровня: Δ = −10 → ×0.5.

Если в сезоне меньше двух «сезонных» игроков, уравнивание не действует (×1).

## 2. Темп развития: 100 реальных часов

### 2.1. Профиль штрафа

До `pacing_start_level` (по умолчанию 20) множитель равен 1 — новичков не трогаем.
Дальше включается плавно растущий штраф:

```
ramp(L) = ((L − start) / (MAX_LEVEL − start)) ^ curve      // 0…1
темп(L) = clamp(1 + k × ramp(L), 0.02 … ∞)
```

`k` — общая «сила» профиля:

* `k = 0` — без изменений;
* `k < 0` — штраф, растущий к максимуму (1 + k на 50-м уровне);
* `k > 0` — ускорение, если сборка проходится быстрее цели.

При `pacing_max_penalty = 0.95` и `curve = 2` на уровнях 20 → 50 множитель идёт так:

| Уровень | 20 | 25 | 30 | 35 | 40 | 45 | 50 |
|---|---|---|---|---|---|---|---|
| Множитель | ×1.00 | ×0.97 | ×0.88 | ×0.76 | ×0.59 | ×0.34 | ×0.05 |

### 2.2. Автоматическая калибровка

Игра измеряет **базовую скорость развития** — сколько реального времени уходит на уровень,
если бы множитель был равен 1. Для этого каждая секунда игры делится на действующий множитель:

```
базовые_секунды += 1 / итоговый_множитель
```

Из замеров по всем игрокам и всех уровней считается скорость «опыта в час» и
экстраполируется на весь путь до максимального уровня с учётом весов опыта
(`LevelUtils.getExpRequiredForLevel`). Пока замеров мало, оценка смешивается с
`assumed_baseline_hours` (40 ч по умолчанию), затем всё больше доверия реальным данным
(полное доверие — после 6 часов суммарных замеров).

Дальше подбирается `k` так, чтобы:

```
базовые_часы × stretch(k) = target_hours
```

где `stretch(k)` — во сколько раз профиль растягивает полный путь до 50-го уровня.
Решение ищется бисекцией; если цель недостижима в пределах
`pacing_max_penalty`/`pacing_max_bonus`, берётся ближайший предел.

С текущей кривой и лимитами (штраф до 95 %, ускорение до +100 %) достижимый диапазон
растяжения — примерно **×0.75 … ×2.4**. Этого достаточно, чтобы из 40-часовой сборки
сделать ~95-часовую. Если нужен более сильный штраф, увеличьте `pacing_max_penalty`
(до 0.99) или `pacing_curve` (кривая 1 даёт более равномерный штраф и больший диапазон).

Точное «100 часов» — всегда оценка: реальное время зависит от стиля игры, AFK,
смертей и т.п. Панель показывает и базовую оценку, и прогноз, чтобы можно было
подкрутить цель.

### 2.3. Реальное время

Считается именно **реальное время** (wall-clock), а не игровые тики. По умолчанию
AFK не учитывается: если игрок не двигался дольше `afk_threshold_seconds` (300 с),
секунды не начисляются (но статистика уровня и множителей обновляется).

### 2.4. Без автокалибровки

Если `pacing_auto_calibrate = false`, `k` фиксируется равным `−pacing_max_penalty`,
то есть на максимальном уровне множитель равен `1 − pacing_max_penalty`.
Удобно, когда нужна предсказуемая «ручка», а не автонастройка.

## 3. Как два режима работают вместе

Множители перемножаются и обрезаются в `[exp_multiplier_min, exp_multiplier_max]`
(по умолчанию 0.05…5.0):

```
итог = clamp(темп × догоняющий × автобаланс, min, max)
```

Поэтому отстающий игрок получает бонус **даже тогда, когда общий темп ещё не растянут
до 100 часов**: глобальный штраф и локальная подстройка независимы. Например:

| Ситуация | темп | догоняющий | итог |
|---|---|---|---|
| 15-й уровень, все равны | ×1.00 | ×1.00 | ×1.00 |
| 35-й уровень, ориентир 35 | ×0.76 | ×1.00 | ×0.76 |
| 20-й уровень, ориентир 35 | ×1.00 | ×3.00 | ×3.00 |
| 40-й уровень, ориентир 35 | ×0.59 | ×0.75 | ×0.44 |
| 47-й уровень, ориентир 30 | ×0.23 | ×0.50 | ×0.12 |

В таблице «×3.00» ограничен `catch_up_max_bonus`, поэтому фактически ×3.

Множитель виден игроку:

* в сообщении о полученном опыте: `+123 опыта x1.85`;
* при входе: `GameMaster: множитель опыта x1.85 (темп x0.62, догоняющий x3)`;
* в команде `/mine_and_slash gm player <ник>`.

Отключить сообщения можно в конфиге (`show_multiplier_in_actionbar`, `announce_on_login`).

## 4. Команды

Все команды требуют прав гейм-мастера (уровень оператора 2):

```
/mine_and_slash gm                                  — сводка: переключатели, цель, прогноз, панель
/mine_and_slash gm status
/mine_and_slash gm catchup                          — вкл/выкл уравнивание
/mine_and_slash gm catchup true|false
/mine_and_slash gm pacing                           — вкл/выкл общий темп
/mine_and_slash gm pacing true|false
/mine_and_slash gm enabled                          — мастер-выключатель (опыт и спавн)
/mine_and_slash gm spawnrate                        — состояние spawn-rate
/mine_and_slash gm spawnrate enabled true|false     — включить/выключить регулировку спавна
/mine_and_slash gm spawnrate dynamic true|false     — динамика от Благосклонности
/mine_and_slash gm spawnrate manual 0.5             — глобальный ручной множитель (0…1)
/mine_and_slash gm spawnrate player <ник>           — текущие настройки игрока
/mine_and_slash gm spawnrate player <ник> 0.5       — ручной override игроку
/mine_and_slash gm spawnrate player <ник> reset      — снять override
/mine_and_slash gm auto                             — состояние автобаланса
/mine_and_slash gm auto on|off                      — вкл/выкл автобаланс
/mine_and_slash gm auto mobs true|false             — разрешить автоподстройку HP/урона мобов
/mine_and_slash gm auto loot true|false             — разрешить автоподстройку лута
/mine_and_slash gm auto minutes 14 70               — коридор «минут на уровень» (старт → максимум)
/mine_and_slash gm web                              — вкл/выкл веб-панель
/mine_and_slash gm web true|false
/mine_and_slash gm hours 100                        — целевые реальные часы
/mine_and_slash gm startlevel 20                    — с какого уровня начинать штраф
/mine_and_slash gm penalty 0.95                     — максимальный штраф (доля)
/mine_and_slash gm player <ник>                     — множитель и статистика игрока
/mine_and_slash gm list                             — все отслеживаемые игроки
/mine_and_slash gm save                             — принудительно сохранить данные
/mine_and_slash gm reload                           — перечитать gamemaster.json
/mine_and_slash gm resetdata confirm                — очистить статистику (необратимо)
```

## 5. Веб-панель

При старте сервера поднимается локальный HTTP-сервер (только JDK, без внешних библиотек):

```
http://127.0.0.1:8787/
```

В консоль при запуске пишется строка `[GameMaster] Панель: http://…`.

Что есть на странице:

* переключатели уравнивания, темпа, мастер-выключателя, регулировки spawn-rate и динамики по Благосклонности;
* поля цели/параметров опыта, глобального ручного spawn-rate, базовой Благосклонности и минимума динамики;
* ручной override spawn-rate для каждого отслеживаемого игрока;
* сводка: базовое время, прогноз с настройкой, цель, ориентир группы, онлайн/всего;
* **график «уровень от реального времени»** — по линии на игрока плюс пунктир цели;
* **график текущих множителей опыта** — сразу видно, кого подтягивает, а кого тормозит;
* таблица игроков: уровень, Благосклонность, время, опыт (факт/база), множители опыта и spawn-rate, последний вход.

Обновление — каждые 5 секунд. Токен не обязателен; если задать `web_token`, страница
открывается как `http://127.0.0.1:8787/?token=…`, а API принимает `?token=` или
заголовок `X-GM-Token`.

### Настройки панели

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `web_enabled` | true | поднимать панель при старте сервера |
| `web_host` | `127.0.0.1` | адрес; `0.0.0.0` — доступ из сети |
| `web_port` | 8787 | порт |
| `web_token` | `""` | необязательный токен доступа |

### API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | страница панели |
| GET | `/api/state` | JSON: конфиг, сводка, игроки, история |
| POST | `/api/config` | JSON с изменяемыми полями, например `{"catch_up": false}` |
| POST | `/api/save` | сохранить данные на диск |

Все обращения к состоянию игры маршалируются в серверный поток Minecraft,
поэтому панель безопасна и не мешает тикам.

### Удалённый сервер

Панель по умолчанию слушает только localhost. Для удалённого сервера проще всего
пробросить порт:

```bash
ssh -L 8787:127.0.0.1:8787 user@server
```

и открыть `http://127.0.0.1:8787/` на своей машине. Либо поставьте `web_host = 0.0.0.0`
и обязательно задайте `web_token`.

## 6. Файлы

| Файл | Что внутри |
|---|---|
| `config/age_of_epoch/gamemaster.json` | все настройки (правится вручную, командой или панелью) |
| `config/age_of_epoch/gamemaster_data.json` | прогресс игроков, история для графиков, замеры времени по уровням |

Данные пишутся атомарно (временный файл + переименование) раз в `save_interval_seconds`
(180 с по умолчанию), при выходе игрока и при остановке сервера. История прореживается,
поэтому файл не растёт бесконечно (не более 1200 точек на игрока).

`resetdata` очищает статистику и замеры, но оставляет конфиг.

## 6b. Автобаланс: «режиссёр» вместо фиксированных часов

Классический режим темпа держит **одну** цель (`target_hours`, например 100 ч) и штрафует
игрока за отклонение от неё. Автобаланс делает наоборот: он не назначает часы, а держит
**коридор темпа** и подстраивает под него игру.

### 6b.1. Целевое время уровня

```
t = ((level − 1) / (maxLevel − 1)) ^ auto_curve
target(level) = auto_start_minutes × (auto_end_minutes / auto_start_minutes) ^ t
```

По умолчанию 14 минут на 1-м уровне → 70 минут на 50-м; сумма целевых времён — **≈28 часов**
до максимума. Геометрическая (а не линейная) интерполяция выбрана потому, что восприятие
времени логарифмическое: разница 14→20 минут ощущается сильнее, чем 64→70.

### 6b.2. Правила

| Правило | Условие | Что делает |
|---|---|---|
| Темп | факт/цель вне мёртвой зоны ±20% | `exp ×= ratio^0.8` (медленно → больше опыта) |
| Спасение | на уровне сидим дольше `target × auto_rescue_factor` | `exp ×1.25`, `loot ×1.25`, состояние `rescue` |
| Тормоз по смертям | смертей в час > `auto_deaths_brake` (2.5) | HP мобов до ×0.85, урон до ×0.75, `exp` до ×1.10 |
| Вызов | смертей < `auto_challenge_deaths` и идём быстрее цели | HP мобов до ×1.20, урон до ×1.15, состояние `push` |
| Усталость | сессия > `auto_session_fatigue_minutes` (150) и уровень тянется | `exp ×1.15`, урон мобов ×0.93 |
| Возврат | перерыв ≥ `auto_welcome_hours` (96 ч) | 30 минут `exp ×1.15`, `loot ×1.20`, урон ×0.95 |

Все множители ограничены: опыт `[auto_exp_min, auto_exp_max]` = 0.35…3.0, HP мобов 0.7…1.35,
урон 0.7…1.3, лут 1.0…1.35. Скорость изменения — не быстрее `auto_exp_step_per_minute`
(0.25/мин) на игрока и `auto_global_step_per_minute` (0.05/мин) для серверных множителей,
поэтому значения не «прыгают» от одного замера.

### 6b.3. Что считается «фактом»

`ema_minutes_per_level` — сглаженное (EMA, α = 0.35) реальное время уровня. Замер делается
в момент повышения уровня по `playtime_seconds` без AFK. Смерти считаются на текущем уровне
(`deaths_since_level` / время уровня), поэтому «плохой вечер» не портит статистику навсегда.
Серверные множители мобов и лута — среднее по всем онлайн-игрокам: одиночный новичок на
сервере из ветеранов не сделает мобов мягкими для всех.

### 6b.4. Почему это «интереснее», чем фиксированные N часов

* Игрок не видит «осталось 63 часа до максимума» — он видит уровень примерно раз в 15–70 минут.
* Сильный игрок получает более крепких мобов (вызов), слабый — мягче (без фрустрации).
* Застрявший получает «спасение» — не нужно идти на форум за бустом опыта.
* Долгие сессии не наказываются, а слегка ускоряются; возврат после перерыва — тёплый.
* Итоговое время до максимума — не константа, а сумма фактических времён уровней:
  на реальных цифрах модели это **≈28–30 часов**, что совпадает с естественным темпом
  после правок энергии/маны (см. `BALANCE-AUDIT.md` и `tools/balance/balance_model.py`).

## 7. Ограничения и нюансы

* Уравнивание и темп влияют только на **опыт уровня персонажа**. Автобаланс дополнительно
  (если включены `auto_touch_mobs`/`auto_touch_loot`) применяет **серверные** множители:
  HP мобов — в `MobStatUtils.getMobBaseStats`, урон обычной атаки — в `EntityData.mobBasicAttack`,
  шанс дропа — в `LootInfo`. Это средние значения по онлайну, а не персональные: урон/HP
  задаются при спавне и пересчёте статов моба, поэтому уже заспавненные мобы реагируют
  с задержкой (до следующего пересчёта).
* Опыт профессий автобаланс не трогает. Spawn-rate — отдельный режим и живёт независимо.
* Множитель опыта применяется ко всем источникам опыта уровня, включая `/mine_and_slash give exp`
  (админ тоже увидит изменённое число — это сознательно, чтобы настройка была единой).
* Уровни ниже `pacing_start_level` не штрафуются — новых игроков темп не душит.
* Оценка базового времени делается по фактическим замерам и весам опыта. Если на высоких
  уровнях скорость опыта заметно падает (или растёт), прогноз будет смещаться — следите
  за колонкой «базовое время» на панели и при необходимости поправьте `assumed_baseline_hours`
  или выключите автокалибровку.
* Секунды засчитываются, пока игрок в мире; нахождение в меню/инвентаре отличить невозможно,
  а AFK определяется по отсутствию движения.
* Изменения конфига применяются сразу, но догоняющий множитель пересчитывается раз в 5 секунд,
  а калибровка темпа — при новых замерах (не чаще раза в 5 секунд).

## 9. Spawn-rate мобов вокруг игроков

Spawn-rate — отдельный режим GameMaster. При `enabled=true` и `spawn_rate_enabled=true`
он регулирует попытки **естественного появления враждебных мобов**, обычные ванильные
блоки-спавнеры и обычные волны спавнеров комнат данжей рядом с ближайшим выжившим игроком.

Эффективный множитель:

```
ручной = player_override, если задан; иначе spawn_rate_manual_multiplier
динамический = clamp(F / (F + Благосклонность), spawn_rate_dynamic_min_multiplier, 1)
итог = clamp(ручной × (spawn_rate_dynamic ? динамический : 1), 0, 1)
```

`F = spawn_rate_favor_reference` (по умолчанию 100). Поэтому при настройках по умолчанию:

| Благосклонность | 0 | 50 | 100 | 200 | 900 |
|---|---:|---:|---:|---:|---:|
| Динамический множитель | ×1.00 | ×0.67 | **×0.50** | ×0.33 | ×0.10 |

При 100 Благосклонности средняя частота попыток спавна уменьшается вдвое. Чем больше
Благосклонность, тем ниже частота; при нуле динамический штраф отсутствует. Значение
`spawn_rate_dynamic_min_multiplier` (по умолчанию 0.05) задаёт нижний предел, чтобы
мобы не исчезли полностью при очень высокой Благосклонности.

Ручная настройка ограничена диапазоном 0…1: `1` не добавляет ручного штрафа, `0.5`
оставляет примерно половину попыток, `0` полностью блокирует регулируемый спавн.
Глобальный ручной множитель можно сочетать с динамикой или отключить её. Override игрока
**заменяет только глобальную ручную часть**; динамика Благосклонности затем всё равно
применяется. Например, при Благосклонности 100 и ручном override ×0.8 итог будет ×0.4.

Настройки в `gamemaster.json`:

| Поле | По умолчанию | Назначение |
|---|---:|---|
| `spawn_rate_enabled` | true | включить регулирование спавна |
| `spawn_rate_dynamic` | true | включить динамику по Благосклонности |
| `spawn_rate_manual_multiplier` | 1.0 | глобальный ручной множитель 0…1 |
| `spawn_rate_favor_reference` | 100 | Благосклонность, при которой динамика даёт ×0.5 |
| `spawn_rate_dynamic_min_multiplier` | 0.05 | минимальный множитель динамики |
| `spawn_rate_player_overrides` | `{}` | UUID → ручной множитель игрока 0…1 |

Управление из игры:

```
/mine_and_slash gm spawnrate                      — показать настройки
/mine_and_slash gm spawnrate enabled false        — выключить spawn-rate
/mine_and_slash gm spawnrate dynamic false        — оставить только ручную настройку
/mine_and_slash gm spawnrate manual 0.75          — общий ручной множитель ×0.75
/mine_and_slash gm spawnrate player Alice 0.5     — ручной override игроку
/mine_and_slash gm spawnrate player Alice reset   — убрать override
```

Веб-панель показывает текущую Благосклонность и итоговый spawn-rate для отслеживаемых
игроков, позволяет менять глобальные параметры и ставить/снимать ручной override.
Команды требуют права оператора 2; конфиг и override сохраняются в
`config/age_of_epoch/gamemaster.json`.

Фильтры: естественная настройка применяется только к враждебным мобам с причиной спавна
`NATURAL`; животные и известные боссы (дракон, визер, хранитель, древний страж и типы с
`boss` в ID) не затрагиваются. Для ванильных блоков-спавнеров тип берётся из SpawnData;
там также пропускаются NBT с тегами боссов башни/данжа и `mmorpg_minion`. Спавнеры комнат
данжей пропускают запланированный вызов босса, но замедляют обычные волны. Прислужники,
созданные игроками, не имеют причины спавна `NATURAL` и не регулируются этой механикой.
Она не меняет моб-капы и не влияет на trial-спавнеры или другие пользовательские спавнеры,
которые не используют ванильный `BaseSpawner` и не подключены к GameMaster.
