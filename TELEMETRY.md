# Телеметрия — «всё обо всём» за сезон

Система собирает **три слоя данных**: сырой журнал событий, агрегаты в реальном времени и
отчёт по сезону. Цель — между сезонами принимать решения по фактам, а не по ощущениям:
что игроки реально делали, где проводили время, от чего умирали, чем пользовались и когда
заходили.

Всё живёт в `config/age_of_epoch/`:

| Что | Файл | Кто пишет |
|---|---|---|
| Агрегаты, сезон, профили | `gamemaster_data.json` | постоянно, раз в `save_interval_seconds` |
| Сырые события | `telemetry/events-<дата>-<id>.jsonl` | на каждое событие (буфер, сброс раз в секунду) |
| Архив прошлых сезонов | `seasons/<сезон>-<timestamp>.json` | при `/gm season new` |
| Отчёт по сезону | `season_report_<сезон>.md` | `/gm telemetry report` и автоматически при смене сезона |

---

## 1. Что собирается

### 1.1 События (журнал JSONL)

Каждая строка — одно событие с полным контекстом:

```json
{"t":1761321600,"season":"season-1","type":"kill","player":"Mira","uuid":"...",
 "subject":"minecraft:zombie","value":1,"dim":"minecraft:overworld",
 "biome":"minecraft:dark_forest","level":23,"extra":""}
```

| `type` | Когда пишется | `subject` | `value` | `extra` |
|---|---|---|---|---|
| `login` | вход на сервер | — | — | — |
| `logout` | выход | — | секунды сессии | — |
| `level` | новый уровень | номер уровня | уровень | — |
| `death` | смерть игрока | причина (`fall`, `mob`, …) | 1 | — |
| `kill` | игрок убил моба | id моба | 1 | — |
| `kill_env` | моб умер без игрока | id моба | 1 | — |
| `loot` | дроп с моба | id моба | сколько выпало | `MOB\|<редкость моба>\|t<tier>` |
| `gear` | сгенерирован предмет | id предмета/редкость | 1 | `rarity=<id>\|lvl=<n>` |
| `spell` | каст способности | id способности | 1 | — |
| `crate` | открыт сундук | id награды | 1 | тип сундука (`Gem`, `Rune`, `Currency`) |
| `retain` | событие удержания | тип | значение | детали |

Событие `kill` пишется на `LivingDeathEvent` — то есть ловит **все** смерти мобов, включая
ванильных, а не только модовых.

### 1.2 Сэмплирование мира

Раз в `telemetry_sample_seconds` (по умолчанию 10 с) для каждого не-AFK игрока фиксируется:

* измерение (`dim_time|minecraft:overworld`);
* биом (`biome_time|minecraft:flower_forest`);
* локальный час (`hour|19`) — для расписания;
* пройденное расстояние (по фактическому смещению, телепорты ≥64 блоков игнорируются).

Из этого складываются профили: «где живёт игрок», «сколько он ходит», «когда играет».

### 1.3 Агрегаты

Счётчики вида `категория|значение` — глобальные и по игрокам. Обновляются в памяти,
мгновенно отдаются в панель, сохраняются вместе с данными GameMaster.

| Префикс | Смысл |
|---|---|
| `biome_time\|` | секунды в биоме |
| `dim_time\|` | секунды в измерении |
| `hour\|` | секунды по локальным часам |
| `kill_mob\|` | убийства по типу моба |
| `kill_biome\|` | убийства по биому |
| `subject_death\|` | смерти по причине |
| `subject_loot\|` | дроп по мобу |
| `subject_gear\|`, `gear_rarity\|` | предметы и их редкость |
| `subject_spell\|` | использования способностей |
| `subject_crate\|` | открытые сундуки и награды |
| `subject_retain\|` | сработавшие механики удержания |
| `event\|` | число событий по типу |
| `distance` | пройденные блоки |
| `play_seconds` | время в игре (без AFK) |
| `session_seconds`, `session_count` | суммарное и число сессий (для средней длины) |
| `subject_chest\|` | сундуки мира/данжей по числу предметов |
| `loot_mob_rarity\|` | редкость мобов, с которых падал дроп |

Лимиты: 5000 глобальных ключей и 300 на игрока. При переполнении выкидываются самые
маленькие значения — «хвост» не распухает.

### 1.4 Чего НЕ собирается

Осознанно:

* **чат и личные сообщения** — это приватность, а не аналитика;
* IP-адреса, UUID устройства, местоположение в реальном мире;
* содержимое инвентаря и сундуков целиком (только факт и редкость добычи).

Всё остальное — можно.

## 2. Реальное время

### Панель

Раздел **«Телеметрия»** обновляется каждые 5 секунд:

* **живая лента** последних событий (время, тип, игрок, предмет/моб, биом, уровень);
* топы за сезон: биомы, измерения, убитые мобы, причины смерти, редкости, способности;
* карточка «Телеметрия» — число событий и дней сезона;
* колонка **«Профиль»** в таблице игроков: стиль (`воин`, `исследователь`, `фарм на месте`,
  `смешанный`) и любимый биом в подсказке.

### HTTP для внешних инструментов

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET | `/api/state` | полное состояние панели (включая `summary.telemetry` и профили) |
| GET | `/api/telemetry` | только телеметрия: топы, лента, профили игроков |
| POST | `/api/report` | записать отчёт по сезону, вернуть путь |
| POST | `/api/config` | изменить настройки (в том числе `telemetry_*`) |

Токен, если задан, передаётся как `?token=…` или заголовком `x-gm-token`.

### Команды

```
/mine_and_slash gm telemetry            — статус + топы (биомы, мобы, смерти, способности)
/mine_and_slash gm telemetry on|off
/mine_and_slash gm telemetry report     — записать season_report_<сезон>.md
/mine_and_slash gm season                — текущий сезон: дни, события, игроки
/mine_and_slash gm season new <название> — отчёт, архив, обнуление счётчиков
```

## 3. Профили и «что нравится игрокам»

Для каждого игрока считается:

| Поле | Как считается |
|---|---|
| `top_biome`, `top_biome_share` | биом с максимумом времени и его доля от всей игры |
| `top_dimension` | измерение с максимумом времени |
| `top_mob` | самый убиваемый моб |
| `top_death` | самая частая причина смерти |
| `top_spell` | самая используемая способность |
| `top_hour` | любимый час игры |
| `kills`, `deaths`, `distance` | сырые числа |
| `style` | эвристика по соотношению убийств, дистанции и добычи |

Стиль (`style`):

* `фарм на месте` — много убийств, мало ходьбы, добыча на убийство > 0.5;
* `исследователь` — 5+ биомов и дистанция ≫ убийств;
* `воин` — больше одного убийства в минуту игры;
* `смешанный` — всё остальное; `мало данных` — меньше 15 минут.

Это не «мнение», а прямые следствия счётчиков — их можно пересчитать из журнала заново.

## 4. Между сезонами: рабочий процесс

1. За несколько дней до конца: `/gm telemetry report` — появляется `season_report_<сезон>.md`.
2. Прочитать раздел **«Выводы и что менять»** — там автоматические правила, например:
   * биомы с долей < 1 % — куда не доходит контент;
   * биом с долей > 50 % — «дом», нужны причины выходить;
   * причина смерти ≥ 30 % — самый дешёвый способ улучшить сезон;
   * смертей < 2 % от убийств — сложность можно поднять;
   * способности не используются — проверить ману/подсказки;
   * меньше 4 игроков с данными — приоритет не контент, а приглашение.
3. При необходимости — выгрузить сырые данные и посчитать своё (см. §5).
4. `/gm season new <название>` — архив `seasons/*.json`, отчёт и чистые счётчики.
   Настройки баланса при этом **не сбрасываются** — их надо менять осознанно.

## 5. Сырые данные: примеры запросов

Журнал — обычный JSONL, читается `jq`, pandas, Excel (через конвертацию).

**Часы по биомам:**

```bash
jq -r 'select(.type=="loot" or .type=="kill") | .biome' telemetry/*.jsonl | sort | uniq -c | sort -rn
```

**Топ причин смерти по игрокам:**

```bash
jq -r 'select(.type=="death") | .player + " " + .subject' telemetry/*.jsonl | sort | uniq -c | sort -rn | head -20
```

**Доля дропа по редкостям (из `gear`):**

```bash
jq -r 'select(.type=="gear") | .extra' telemetry/*.jsonl | sed 's/|.*//' | sort | uniq -c
```

**pandas:**

```python
import pandas as pd, glob
df = pd.concat(pd.read_json(f, lines=True) for f in glob.glob("config/age_of_epoch/telemetry/*.jsonl"))
kills = df[df.type == "kill"].groupby(["player", "subject"]).size().sort_values(ascending=False)
biomes = df[df.type.isin(["kill", "loot"])].groupby("biome").size().sort_values(ascending=False)
```

**Средняя длина сессии:**

```python
sessions = df[(df.type == "logout") & (df.value > 60)].groupby("player").value.mean() / 60
```

## 6. Производительность и хранение

* Запись в журнал — буферизованная, сброс раз в секунду; при 6 игроках это десятки строк
  в минуту, не в тик.
* Файл журнала ротируется по размеру (`telemetry_max_file_mb`, по умолчанию 16 МБ)
  и по дате; старые удаляются через `telemetry_retention_days` (60 дней).
* Агрегаты — только в памяти и в `gamemaster_data.json`, без отдельных файлов.
* Любая ошибка телеметрии гасится и логируется не чаще раза в минуту: **игру она не ломает**.

## 7. Настройки

```json
{
  "telemetry_enabled": true,
  "telemetry_events": true,
  "telemetry_sample_seconds": 10,
  "telemetry_max_file_mb": 16,
  "telemetry_retention_days": 60,
  "telemetry_season": "season-1",
  "telemetry_panel_top": 8
}
```

`telemetry_events = false` оставляет агрегаты и панель, но не пишет журнал (экономия диска).

## 8. Как добавить свой сигнал

Одна строка в любом месте кода, где есть `ServerPlayer`:

```java
GameMaster.get().telemetry().event("trade", player, itemId, amount, "npc=merchant");
```

Она сразу попадёт в живую ленту, в счётчик `subject_trade|<itemId>` и в журнал — без правок
панели, отчёта и схемы данных.
